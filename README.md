# Job Search Assistant

Локальный помощник для поиска работы на Go с веб-интерфейсом. Письма в интерфейсе и пакетный разбор подборок создаёт Codex CLI. Автоматизирует рутину: ищет вакансии, помогает с резюме и откликами, ведёт учёт всех откликнутых позиций.

## Что умеет

- **Искать вакансии** по hh.ru, Habr Career и Hirify с учётом вашего профиля
- **Писать и редактировать резюме** по формуле Google XYZ — с метриками, цифрами и привязкой к стеку вакансии
- **Собирать PDF-резюме** из готового двухколоночного шаблона
- **Адаптировать резюме под конкретную вакансию** — переписывать буллеты, подсвечивать релевантный опыт
- **Анализировать пробелы:** что не хватает в резюме под вакансию, что подучить
- **Писать отклики и ответы рекрутёрам**, подстраивая тон под стиль исходного сообщения. Без признаков AI-генерации
- **Вести историю откликов:** каждый отклик и вся переписка по вакансии сохраняются в отдельный файл со статусом

## Установка

```bash
git clone <repo>
cd job-search
pip install weasyprint
```

Требуется:

- Codex CLI с авторизацией через `codex login` (для писем и пакетного разбора подборок)
- Python 3 (для сборки PDF из шаблона)
- Bash
- Go 1.25+ (для веб-сервера и сборщика вакансий)

## Как пользоваться

Положите резюме (PDF или Markdown) в `resumes/` и откройте Codex из корня репозитория:

```bash
codex
```

В первой сессии агент задаст несколько вопросов о вашем профиле: целевая роль, стек, опыт, формат работы, рынки. Дальше всё работает через обычный чат.

### Веб-интерфейс

```bash
make ui
```

Откройте http://127.0.0.1:8080. Сервер написан на Go; установка frontend-зависимостей не требуется. При первом запуске Go скачает зависимости.
Интерфейс читает `jobs/raw/*.json`: поиск по должности, компании и описанию, фильтры по подборке, источнику, удалёнке и зарплате. Повторные вакансии объединяются по URL. Есть избранное, личные статусы и заметки с автоматическим сохранением в localStorage этого браузера. Они не синхронизируются с `applications/` и другими браузерами. Сервер доступен только на localhost и отдаёт только интерфейс и выгрузки вакансий.

Перед запуском раскройте «Параметры новой подборки»: выберите направление, Junior/Middle/Senior/Lead (можно несколько), ключевые слова и удалённый формат. Backend без выбранных уровней ищет все уровни вместо запросов из профиля. «По моему профилю» сохраняет прежние поисковые запросы. Ключевые слова уточняют поиск; если указано несколько, должны встретиться все. Уровень определяется по названию: при выбранном уровне вакансии без явного грейда исключаются. Удалёнка учитывается только если источник её явно указал.

Параметры формы сохраняются в браузере; параметры запуска — в `search_filters` внутри выгрузки и отображаются при выборе подборки. Профиль на диске не изменяется. Поиск использует существующие источники и их ограничения по выдаче, датам и страницам; «все уровни» не означает полную выгрузку сайта. Уже просмотренные вакансии и компании из чёрного списка по-прежнему исключаются.

«Найти новые вакансии» запускает `run-search.sh` в фоне: Go собирает вакансии, затем Codex CLI разбирает их и пишет отчёт. Нужны настроенный Codex CLI, профиль и зависимости обычного поиска. Прогресс показывает фактические этапы: подготовка, hh.ru, Hirify, Habr Career и разбор результатов. Полоса отражает число завершённых этапов, а не оценку оставшегося времени; рядом отображается длительность поиска. Повторный запуск блокируется на время работы. Во время поиска кнопка меняется на «Отменить поиск»: она останавливает текущий процесс и его дочерние процессы. Пока остановка не завершена, отображается «Отменяем…»; затем можно запустить новый поиск. Уже сохранённые подборки остаются доступны. После завершения подборки перечитываются автоматически. «Перечитать список» рядом со списком вакансий только загружает уже сохранённые данные и не запускает поиск на сайтах. Отклики интерфейс не отправляет; выгрузки могут содержать уже закрытые вакансии.

Go-сервер находится в `backend/server/`: Fiber, `controllers → handlers → repository`, конфигурация через configor, логирование через logrus. API: `GET /api/runs`, `GET /api/search`, `POST /api/search` (JSON, с того же origin). Тело запроса: `{"direction":"backend","levels":["junior","middle"],"query":"Go","remote_only":true}`; `{}` запускает поиск по профилю. Неизвестные поля и значения возвращают 400. Отмена: `POST /api/search/cancel` с `{}`. Статусы поиска: `idle`, `running`, `canceling`, `canceled`, `succeeded`, `failed`. Состояние поиска хранится в памяти сервера; закрытие вкладки не останавливает поиск, остановка сервера завершает его дочерние процессы.

Настройки сервера: `JOB_SEARCH_PORT` (8080), `JOB_SEARCH_ROOT` (по умолчанию `../..` относительно `backend/server`), `JOB_SEARCH_TIMEOUT` (30m на весь процесс). Сервер слушает только `127.0.0.1`. Например: `JOB_SEARCH_PORT=8081 make ui`. Лог запуска: `logs/web-search.log`; подробные логи поиска: `logs/search.log` и `logs/search-debug.log`.

Проверка бэкенда без запуска реального поиска:

```bash
cd backend/server
go test -race ./...
go vet ./...
go build ./...
```

Агенты разработки в `.codex/agents/go-*.toml` адаптированы из hc2/be: integrator реализует, reviewer проверяет, orchestrator координирует большие задачи, tester выполняет ручную проверку по запросу.

### Мои резюме

Раздел «Мои резюме» в боковой панели позволяет загрузить PDF (до 8 МБ) или Markdown (до 100 КБ), создать текстовое резюме с нуля, редактировать и сохранять его, посмотреть текст и скачать файл. Резюме сохраняются в `resumes/` и сразу доступны для сопроводительного письма.

PDF остаётся оригиналом: «Создать редактируемую копию» переносит извлечённый текст в новый Markdown-файл. Вёрстка PDF при этом не сохраняется; проверьте порядок текста. Для извлечения нужен `pdftotext`. Предпросмотр показывает текст, а не точный PDF-макет. Файл с существующим именем не перезаписывается при загрузке. При конфликте сохранения правки остаются в редакторе и могут быть сохранены отдельной копией.

«Использовать для откликов» сохраняет выбор по умолчанию в этом браузере. Переход к вакансиям сохраняет открытый редактор; перед закрытием страницы сохраните изменения.

### Сопроводительное письмо из карточки

Нажмите «Написать сопроводительное письмо», выберите PDF/Markdown-резюме из `resumes/` и нажмите «Создать черновик». При необходимости вставьте полное описание вакансии. Генерация использует Codex CLI с существующей локальной авторизацией; для PDF нужен `pdftotext` (Poppler). Если вход ещё не выполнен, запустите `codex login`. Настройки: `JOB_DRAFT_MODEL` (необязательно, модель Codex; без значения используется стандартная модель CLI) и `JOB_DRAFT_TIMEOUT` (по умолчанию `2m`). Старое значение `haiku` нужно убрать.

Генерация выполняется отдельным `codex exec` во временной папке, с резюме и вакансией через stdin. Используется существующее хранилище авторизации Codex; пользовательский конфиг для этого запуска не загружается. Пакетный поиск и разбор через `run-search.sh` используют Codex CLI. Модель можно задать переменной `JOB_SEARCH_MODEL`; без неё используется стандартная модель CLI.

Результат — короткий отклик на языке вакансии с опорой на выбранное резюме. Проверьте факты, отредактируйте текст и нажмите «Сохранить изменения» или «Скопировать». Файл сохраняется в `applications/` со статусом «черновик»; новый вариант создаёт отдельный файл. Кнопка не отправляет письмо и не меняет статус вакансии на «откликнулся».

Пока генерация идёт, можно переключаться между вакансиями. Состояние редактора хранится в открытой странице; перед закрытием сохраняйте правки. После перезапуска сервера созданные файлы остаются в `applications/`.

### Запуск поиска

```bash
./run-search.sh
```

Скрипт запускает агента, тот обходит источники, формирует отчёт в `jobs/YYYY-MM-DD-HHMM.md`. Дальше в чате:

> Посмотри последний файл из jobs, какие вакансии стоят внимания?

### Адаптация резюме под вакансию

> Адаптируй моё резюме под эту вакансию: <ссылка или текст>

Агент перепишет буллеты под требования и стек вакансии. После можно сразу попросить собрать PDF.

### Анализ пробелов

> Чего не хватает в моём резюме под эту вакансию: <ссылка>?

Получите список расхождений и приоритетный план «что подучить».

### Отклик на вакансию

> Напиши отклик на <ссылка>

Файл с откликом, URL вакансии и статусом сохранится в `applications/`.

### Ответ рекрутёру

> Рекрутёр прислал: "<сообщение>". Как ответить?

Ответ подгоняется под тон рекрутёра (casual / friendly / business / direct). Переписка дозаписывается в существующий файл вакансии — вся история в одном месте.

## Скиллы

В `.agents/skills/` лежат правила, по которым работает агент. Загружаются по триггеру.

- **`resume`** — написание и редактирование резюме, генерация PDF
- **`application`** — отклики и переписка с рекрутёрами, история откликов

## Кастомизация

| Что менять | Где |
|-----------|-----|
| Дизайн резюме | `.agents/skills/resume/templates/two-column.html` |
| Правила написания резюме | `.agents/skills/resume/SKILL.md` |
| Правила откликов | `.agents/skills/application/SKILL.md` |
| Источники и фильтры поиска | `config/search-config.md` |
| Профиль кандидата | `config/user-profile.md` |
| Профиль и общие инструкции | `CLAUDE.md` |
